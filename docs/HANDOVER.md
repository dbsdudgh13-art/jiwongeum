### 2. 전략작물직불의 미해결 쟁점

`policy-guard` 가 반려했고 아직 안 고쳤다. 두 게이트의 판정이 갈렸던 건이다.

- `fact-checker`: 「ha당 50만~600만원」은 원본 `support` 필드에 그대로 있는 문구다. 인용이 맞다.
- `policy-guard`: 인용이어도 **배치**가 문제다. 본문에서 도달 가능한 최대는 500만원
  (하계조사료 단독) 또는 300만원(두류·가루쌀 200 + 이모작 100)인데, description 과 h2 가
  전면에 600만원을 내세운다. 독자는 원본 필드를 볼 수 없고 본문만 본다.

`policy-guard` 판단이 맞다. 수정 방향도 제시해 두었다.

1. 600만원에 도달하는 조합을 원본 공고에서 다시 확인해 본문에 명시하거나
2. 못 찾으면 상단 노출 수치를 본문에서 실증되는 범위(50만~500만원)로 낮추고, 원본 문구는
   본문 안에 캐비엇으로만 남긴다

### 3. 가사·간병(`vou000000040`) 처리

1회차에 3회 연속 반려됐고 사용자가 보류를 승인했다. 원자료 998자로 본문 분량을 감당하지
못해 고칠 때마다 다른 자리에서 창작이 나왔다. 지금은 후보 기준선이 1,200자로 올라가
같은 사례가 다시 들어오지 않는다. 이 문서는 **폐기하거나 대폭 줄여서 발행**해야 한다.
사용자에게 물어라.

### 4. 새 회차 대상 선정

`node scripts/candidates.mjs 300` 으로 후보를 뽑고 `scout` 에게 넘긴다.
현재 기준(원자료 1,200자 이상, 미발행, 신청 가능, 기관당 3건)으로 231건이 남는다.

## 반드시 알아야 할 것

### 사용자가 하는 일은 `업데이트` 한 마디뿐이다

나머지는 전부 에이전트가 한다. 사용자에게 확인을 요청하는 경우는 규칙이 정한 때뿐이다.

- 같은 문서가 2회 연속 FAIL (무한 재작업 금지)
- 발행된 문서의 원자료가 바뀌어 해설 재작성이 필요할 때

### 검수 게이트를 우회하지 마라

`fact-checker` 와 `policy-guard` 는 거부권을 가진다. 결과를 무시하고 발행하지 않는다.
`reviewed: true` 는 **둘 다 통과한 뒤에만** `seo-editor` 가 올린다.

### writer 호출 프롬프트에 문서 구조를 적지 마라

1·2차 반려의 원인이었다. h2 제목 목록을 프롬프트에 박아 넣었더니 여러 문서가 같은 골격으로
나왔다. 구조는 `.claude/agents/writer.md` 한 곳에서만 정의한다.

프롬프트에는 이것만 적는다.

- 대상 파일 경로, 원본 레코드 경로
- 그 제도에만 해당하는 위험 (예: 널리 알려진 수치라 상식으로 채울 위험, 융자인데 지원금으로
  오해할 위험, 지역 한정인데 전국으로 읽힐 위험)

### 16MB 파일을 에이전트에게 읽히지 마라

`data/normalized/services.json` 은 16MB다. 서비스 한 건씩 잘라 임시 파일로 넘긴다.

```js
// 큐의 항목별로 레코드를 추출하는 코드
const {checkedAt, services} = JSON.parse(fs.readFileSync('data/normalized/services.json','utf8'));
const byId = new Map(services.map(s => [s.id, s]));
// scratchpad 에 <id>.json 으로 저장해 프롬프트에 경로만 준다
```

후보 선별은 `scripts/candidates.mjs` 가 기계적으로 한다.

### 발행 전에 `npm run contentcheck` 를 돌려라

기계로 확정되는 결함만 잡는다. 판단이 필요한 것은 에이전트 몫이다.

- 마크다운에 섞인 `</content>` 류 태그
- `updated` 날짜의 따옴표 누락 — **없으면 빌드가 통째로 실패한다.** 두 번 겪었다
- 독자에게 내부 데이터를 지칭하는 표현(「원본 자료」 등)
- AdSense 과장 표현
- 본문 800자 미달, FAQ 개수
- 같은 h2 가 3개 이상 문서에 반복
- 적발된 상투구 (아래)

## 지금까지 반복된 실패 유형

새 회차에서 같은 것이 나오면 즉시 알아볼 수 있게 정리한다.

### 원본보다 좁게 쓰기 — 가장 위험하다

자격 있는 사람이 신청을 포기한다. 창작보다 눈에 안 띈다.

- 전략작물직불: 제외 대상 4개 중 「농지전용 신고·허가를 거친 농지」 누락
- 방문건강관리: 「장기요양등급자 포함(4~5등급 중심)」을 「4~5등급자」로 한정
- 행복주택: 5년 제한이 2·3번 항목에만 붙는데 청년 유형 전체로 일반화
- 고용안정장려금: 「(대체인력보다 나중에 고용된 근로자는 제외)」 괄호 예외 누락

**괄호 안 예외를 특히 자주 빠뜨린다.** 목록은 원본 항목 수를 세어 맞춰라.

### 원본보다 넓게 쓰기

자격 없는 사람이 헛되이 준비한다.

- 고용안정장려금: 대체인력 채용 시점 제한(「출산전후휴가 시작일 전 2개월 이후」) 누락

### 없는 배경 설명 덧붙이기

- 행복주택: 「대기 방식이 다릅니다」, 「같은 집을 두고도 유형별로 경쟁하는 구조입니다」
- 행복주택: 「직장이나 **학교**와 가까운 곳에」 — 원본은 「직주근접」만
- 가사·간병: 「공고에 표가 붙어 있지 않고」, 「요양보호사가 방문해서」

**본문이 원자료보다 길어지면 이런 문장이 섞였다는 신호다.** 비율을 확인하라.

```
원자료 길이 = support + target + criteria
비율이 0.95 를 넘으면 의심, 1.0 을 넘으면 거의 확실
```

### 제목이 원본보다 많이 주장하기

h2 제목도 사실 주장이다. 본문에서 유보한 것을 제목에서 단정하면 반려된다.

- 「주민센터에서 정해진 기간에 신청」 — 원본 `applyMethod` 가 불명확한데 방문 접수로 단정
- 「시기는 지역마다 다르다」 — 원본 `period` 는 「접수기관 별 상이」

`receiver`(접수기관)와 `applyMethod`(신청방법)는 **다른 필드다.** 섞지 마라.

### 상투구 반복

제목이 전부 고유해도 문장 틀이 같으면 「겉만 바꾼」 대량생성으로 판정된다. 2회차에 이
사유로 5건이 한꺼번에 반려됐다. 적발된 것들은 `contentcheck` 가 막는다.

```
[기관]가 운영하는 사업으로 / ~사업입니다
~가 안내되어 있고, 접수는 ~
확인하는 것이 정확합니다
(시기|기간)은 접수기관마다 다르~
```

**어미를 바꿔 검사를 피하려 하지 마라.** 실제로 「다르다 → 다르므로 → 다릅니다」로 세 번
회피한 적이 있어 패턴 매칭으로 바꿨다. 해법은 **그 제도에서 실제로 중요한 것부터 쓰는 것**
이다. 신청 방법 문단이 가장 잘 겹치는데, 접수처가 하나뿐이면 그것을, 기간이 정해져 있으면
그것을, 온라인이 안 되면 그것을 먼저 말하면 문장이 갈린다.

### 독자에게 내부 사정 말하기

「원본 자료에는 접수 기관이 비어 있어」 같은 표현. 정부 문서를 가리킬 때는 「공고」라고 쓴다.
「원본 공고」는 정상, 「원본 자료」는 위반.

## 원본 데이터 자체의 오류

정부 데이터에 오기가 있다. 발견하면 처리 방식을 구분하라.

| 사례 | 처리 |
|---|---|
| 행복주택 고령자 자동차 가액 `3,708억원` (다른 유형은 3,708만원) | 금액이라 임의 수정 위험 → **수치 빼고 공고 확인으로 유보** |
| 영유아보육료 취학아동 구간 `'19.1.~'13.12.31` (날짜 역순) | 정정이 자명 → **순서만 바로잡고 사실은 추가 안 함** |
| 조기폐차 `화물·특수 차량 100만 원, 그 외 차량` (문장 절단) | 금액이 없음 → **언급하지 않음** |

## 인프라에서 겪은 문제와 해법

같은 것이 재발하면 바로 알아볼 수 있게 남긴다.

| 증상 | 원인 | 해법 |
|---|---|---|
| Actions `fetch` Invalid URL | 미등록 Actions 변수가 `undefined` 가 아니라 빈 문자열로 주입됨. `??` 로 받아 통과 | `resolveEndpoint()` 로 분리, 빈 문자열도 기본값. 회귀 테스트 있음 |
| 링크 6건 전부 사망 판정 | gov.kr 이 해외 IP 차단. GitHub 러너에서 실행됨 | 워크플로에서 `linkcheck` 제거. 절반 이상 실패 시 결과 폐기하는 가드 추가. **국내에서만 실행** |
| 변경분이 PR 로 안 나옴 | 닫힌 PR 의 브랜치가 남아 재사용됨 | `delete-branch: true` |
| PR 생성 실패 | 저장소 설정에서 Actions 의 PR 생성 권한이 꺼져 있었음 | Settings → Actions → General → Workflow permissions 에서 켬 |
| 빌드가 통째로 실패 | `updated` 날짜에 따옴표가 없어 YAML 이 Date 로 파싱 | `contentcheck` 가 막는다 |
| 옛 데이터에 오늘 날짜가 찍힘 | 오래된 `data/raw` 로 `normalize` 실행 | 24시간 넘으면 중단하는 가드 추가 |

## 사용자에 관해

- 비개발자다. 명령어는 실행할 수 있지만 코드는 읽지 않는다. GitHub·Cloudflare UI 는
  화면을 보고 따라가는 수준이니 **단계별로 구체적으로** 안내해야 한다.
- 한국어로 소통한다.
- 인증키를 채팅에 붙여넣은 적이 있다. 재발급을 권했다. **키를 채팅으로 요구하지 마라.**
  편집기로 `.env` 에 직접 넣게 안내한다.
- 세션 한도에 두 번 걸렸다. **작업을 자주 커밋해 두어라.**
